# luci-app-xlnetacc
适用于 OpenWRT/LEDE 纯Shell实现的迅雷快鸟客户端

依赖: wget openssl-util jshn curl ca-bundle


更新到支持快鸟新协议 300

详情见恩山论坛介绍帖 [依然是改良作品，这次的目标是 -- 迅雷快鸟](http://www.right.com.cn/forum/thread-267641-1-1.html)

# Fix
* 增加验证码获取，解决 "为了您的帐号安全，请输入图形验证码[6]" 问题，不建议开启帐号重新登录
* 适配高版本 OpenWRT
* 支持配置兼容 Chat Completions 的图片识别服务，未配置 API Key 时使用手动输入

## 验证码识别配置（1.1.0）

在 LuCI「迅雷快鸟」设置中填写识别服务地址、API Key 和实际支持图片输入的模型名称。
例如兼容服务的 Base URL 可填写 `https://api.example.com/v1`，插件会调用
`/v1/chat/completions`；也接受完整的 `/chat/completions` 地址。模型名以服务端配置为准，
不再在未填写时回退到内置的免费模型。升级会保留已有 UCI 配置。

| 配置 | 默认值 | 说明 |
| --- | --- | --- |
| 识别请求超时 | 90 秒 | 单次请求总时限，可设 15–180 秒；连接超时为 5 秒 |
| 模型输出额度 | 1024 | 可设 64–8192；推理模型可能需要更大的额度 |
| 验证码长度 | 4–8 位 | 仅接受英文字母和数字；可按实际图片固定长度 |

先保存并应用配置，再点击「测试识别服务」。此测试发送一张内容为 `TEST` 的普通文字图片，
验证连接、鉴权、响应格式和图片输入能力，不登录迅雷，也不会使用当前验证码。
它不能保证实际验证码的识别准确率。测试在后台运行，页面轮询显示结果。

### 499 与超时

旧版 AI 请求复用 `wget -T 5`，模型超过 5 秒没有返回数据时，路由器会断开，代理可能记录 499。
新版识别请求使用独立的 curl 总超时，遵循系统路由，不继承提速接口的源地址绑定。
迅雷登录、提速和心跳仍使用原有的 wget 配置。

识别日志显示 HTTP 状态、curl 退出码、请求耗时和错误类别；不输出 API Key、验证码 KEY、
图片内容或原始服务端错误正文。HTTP 401/403、参数或模型错误、429 不自动重试。
网络错误和临时服务故障延迟 3 秒后最多重试一次，重试期间使用同一组图片和 KEY。

### 自动重试与人工输入

只有迅雷返回需要验证码的错误码 6 时才开始验证码流程。自动识别结果必须通过格式校验，
每轮最多提交三次自动识别结果。只有服务端明确拒绝验证码后才自动换图；
识别服务失败、结果格式错误或次数达到上限后，在页面显示图片和输入框供人工处理。

人工输入窗口为 180 秒，支持提交和刷新图片。超时后可点击「重新获取验证码」唤醒登录，
不必等待原有的 130 分钟冷却结束。刷新不会延长本轮人工输入窗口。
新图片会清空旧答案，服务端拒绝属于旧图片的提交。图片及 KEY 保存于权限受限的
`/var/run/xlnetacc`，图片仅通过已登录的 LuCI 页面提供，不再放入公开静态目录。
旧版通过 `/tmp/xlnetacc_verify_code` 写答案的方式由页面提交替代。

### 开发验证

```sh
python -m pip install lupa==2.8
python -m unittest discover -s tests -v
node tests/test_ui.js
```

测试使用本地模拟 HTTP 服务和 LuCI/jshn 测试替身，不请求真实 CPA 或迅雷。
覆盖超过 5 秒的响应、超时与错误分类、请求 JSON、重试上限、旧验证码、CSRF 和页面交互。
GitHub Actions 自动执行这些检查，并为涉及插件文件的 PR 编译 IPK。
也可在 Actions 中手动运行「Build IPK」，从完成后的 Artifacts 下载 `luci-app-xlnetacc-ipk`。
默认只上传构建产物；手动勾选 `publish_release` 才会发布 GitHub Release。
在真实 OpenWrt 上还应验证依赖安装、LuCI 显示，以及服务端返回的验证码格式和有效期。
